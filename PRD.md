# National Catalog API Client - Product Requirements Document

## Overview
Проект представляет собой Python-клиент для работы с API Национального Каталога маркированных товаров (Честный Знак). 

## Цель
Автоматизация получения данных о товарах из Национального Каталога и сохранение их в локальную базу данных SQLite для последующего анализа и использования.

## Функциональные требования

### Этап 1: Получение списка товаров ✅
- Выполнение GET-запроса к endpoint `/v4/product-list` API Национального Каталога
- Параметры запроса:
  - `from_date`: Дата начала периода (формат: YYYY-MM-DD HH:MM:SS)
  - `to_date`: Дата окончания периода (формат: YYYY-MM-DD HH:MM:SS)
  - `limit`: Количество записей за один запрос (максимум 1000)
  - `good_status`: Статус карточки товара (например, `published`)
  - `apikey`: Ключ доступа API

- Сохранение полученных данных в SQLite базу данных `catalog.db`

### Этап 2: Загрузка детальной информации и атрибутов ✅
- Использование endpoint `/v3/feed-product` для получения полной информации о товарах
- Пакетная обработка товаров (до 25 в одном запросе)
- Сохранение следующих данных:
  - Расширенная информация о товаре (производитель, даты, флаги маркировки)
  - Категории товара
  - Атрибуты товара (размеры, цвета, состав, материалы и др.)
  - Изображения товаров
  - Идентификаторы (GTIN, уровни упаковки)

### Структура данных товара (product-list)
| Поле | Тип | Описание |
|------|-----|----------|
| good_id | integer | Идентификатор карточки в системе Честный Знак |
| gtin | string | Global Trade Item Number в системе GS1 Rus |
| good_name | string | Торговое наименование товара |
| tnved | string | Товарная номенклатура ВЭД ЕАЭС |
| brand_name | string | Торговая марка |
| good_status | string | Технологический статус карточки товара |
| good_detailed_status | array | Массив текущих статусов карточки товара |
| updated_date | string | Дата обновления технологического статуса |

### Расширенная структура данных (feed-product)
| Группа полей | Описание |
|--------------|----------|
| **Основная информация** | is_sim, is_kit, is_set, good_img, good_signed, good_mark_flag, good_turn_flag |
| **Даты** | create_date, update_date, first_sign_date |
| **Производитель** | producer_inn, producer_name |
| **Бренд** | brand_id, brand_name |
| **Категории** | cat_id, cat_name (множественные) |
| **Атрибуты** | attr_id, attr_name, attr_value, attr_type, unit, is_required, first_layer |
| **Изображения** | photo_type, image_url (множественные) |
| **Идентификаторы** | identifier_type, identifier_value, packaging_level |

## Технические требования

### Зависимости
- Python 3.8+
- requests (HTTP-запросы)
- python-dotenv (управление переменными окружения)

### Конфигурация
- API ключ хранится в файле `.env`
- URL API: продуктивная среда `https://апи.национальный-каталог.рф`
- Настройки пакетной обработки: размер пачки, задержки между запросами

### База данных
- SQLite в файле `catalog.db`
- Таблицы:
  - `products` - основная информация о товарах (расширенная)
  - `product_categories` - категории товаров
  - `product_attributes` - атрибуты товаров
  - `product_images` - изображения товаров
  - `product_identifiers` - идентификаторы товаров

## Нефункциональные требования
- Обработка ошибок API (400, 403, 404, 429, 503)
- Логирование основных событий
- Соблюдение лимитов запросов к API (500 запросов за 5 минут)
- Автоматическая повторная попытка при получении 429 (Too Many Requests)
- Поддержка ETag для оптимизации повторных запросов (планируется)

## Скрипты проекта

| Скрипт | Назначение |
|--------|------------|
| `catalog_client.py` | Первичная загрузка списка товаров через /v4/product-list |
| `migrate_db.py` | Миграция БД: создание дополнительных таблиц и полей |
| `load_attributes.py` | Загрузка детальной информации и атрибутов через /v3/feed-product |

## Порядок использования

1. Настроить `.env` файл с API ключом
2. Запустить `python catalog_client.py` для получения списка товаров
3. Запустить `python migrate_db.py` для расширения структуры БД
4. Запустить `python load_attributes.py` для загрузки атрибутов
